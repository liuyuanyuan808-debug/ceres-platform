# Ceres 3期需求原型

Ceres 吸奶器管理平台3期交互原型。目标由 Ceres 统一维护设备的新旧韵律及配置版本，AIoT 接收并透传韵律，负责 App 端展示设计与配置。当前 AIoT 维护旧韵律并支持新韵律传入；本期在 Ceres 补齐旧韵律管理能力。

原型默认进入新增的旧韵律页面，覆盖以下功能：

- 动力源方案管理（3期新增版本管理：草稿、停用升版、历史快照与对比）
- 模式单元库
- 模式库
- 韵律管理
  - 新韵律（现有韵律库，独立页面）
  - 旧韵律（3期新增，独立页面；已有共用编排，按型号补充动力源方案及固定版本，展示关联度、待关联红点和原系统发布状态）
- 模式单元频率策略与可选 Speed 分档

在本目录运行 `python3 -m http.server 8173`，打开 `http://localhost:8173/` 即可预览。

变更范围及演示约定见「需求变更说明.md」。发布使用独立的 `/v3/` 路径。

“吸乳方案配置”下的“韵律管理”可展开、收起，下设“新韵律”和“旧韵律（3期新增）”两个独立页面。

按型号和实际固件分发的规则见三期需求文档：旧韵律库存量编排与设备采用的传输协议分开判断。旧编排若通过新协议下发，需补充适用型号的动力源方案及真实执行适配；关联方案不自动改变型号协议，也不代表已具备下发能力。固件仍校验协议兼容范围，本期不支持跨协议固件升级。标签仅用于匹配池内内容投放。本原型不包含独立投放管理或实际 OTA 页面。

2026-11-12：新旧韵律统一为“韵律命名主行 → 型号配置明细”。主行明确维护归属关系，不再按名称与总时长自动合并。同一韵律的模式顺序、节奏与时长由共性编排统一维护；旧韵律的型号明细重点维护动力源关联，新韵律继续维护模式解析得到的完整执行参数。

旧韵律已有模式顺序和时长，主要待补充的是各型号适用的动力源方案。列表展示“动力源关联度”，红点表示待关联；查看或暂存未完成关联不会清点，保存适用的已发布方案及固定版本后仅更新当前型号的关联状态。历史频率、档位由设备端定义，作为历史资料只读保留，不要求重新填写，也不直接视为新协议参数映射。原系统发布 / 停用状态独立保留，动力源关联不会将其改成 Ceres 新协议已发布。

已关联不等于可下发：只有真实模式映射和执行快照完成适配校验，才能进入新协议发布流程；没有适用的已发布动力源时先维护动力源。新韵律继续按完整执行参数及固定快照校验。已发布的 Ceres 配置需要调整时，使用“创建新版本”，在同一韵律的目标型号下生成下一版本草稿，无需先停用。版本号按型号自动递增为 V1、V2、V3；已有草稿则继续编辑该草稿。草稿不覆盖当前已发布快照，历史版本可只读查看。

2026-11-13：去除绿色变更框及重复说明，列表、型号展开和详情沿用模式库、模式单元的标准后台样式。型号档位参数档案及导入界面去除黄色变更底色。新旧韵律仍保持两个独立导航入口，列表和详情布局一致；新韵律展示模式组合及按型号解析得到的完整参数。交互数据保存在独立的演示存储中，不连接实际 AIoT 或设备。

2026-11-15：韵律版本与动力源方案版本分别管理。“创建新版本”保留韵律名称与归属关系，先明确目标型号，按该型号生成或复用新版本草稿；不再把版本号填写在新韵律名称中。列表继续按韵律或型号查看，型号数及发布概况不重复统计历史版本。

2026-11-15 编排展示补充：按韵律查看的名称下方，以及按型号查看的韵律明细，均展示完整的“模式＋分钟数”顺序；同一韵律在各型号上的编排节奏和时间一致，差异仅在设备下发参数。Milk Boost 演示统一为“刺激 2 分 → 吸乳 8 分 → 刺激 2 分 → 吸乳 8 分”，共 20 分钟。型号参数编辑保留共性模式及时长只读，型号参数版本仍独立管理。现有 Milk Boost 当前演示配置及草稿对齐该模板并保留原阶段备份，正式历史版本不改；其他已有韵律从一致的实际阶段推导共性编排，缺少或冲突的数据不编造时长。

2026-11-15 旧韵律动力源补充：补充入口以动力源方案及固定版本为主，共用编排只读；取消将缺少历史频率、档位作为动力源关联的必填门槛，也不再要求“与原系统参数一致”的补录确认。既有自动匹配或示例方案不作为已确认关联，历史字段及已发布快照保留。
